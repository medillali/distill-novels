# 你的本地小说资料库

你可以继续用自然语言工作，不必自己编写 JSON。当前工作区已设置恢复入口，之后在同一 Novel 项目新开会话时，Codex 会从 `AGENTS.md` 找到工具与资料库。

## 现在从哪里进入

| 位置 | 用途 |
|---|---|
| `../writing-vault/` | 真实个人资料库，初始化为空，供以后长期积累 |
| `work/demo-final/START-HERE.md` | 完全原创的功能演示，不进入真实资料库 |
| `work/demo-final/source-view/index.html` | 可双击打开的离线来源分析图，含章节证据 |
| `../小说工作台.md` | 工作区总入口与常用说法 |
| `../novel.cmd` | 本机快捷命令，自动选择可用 Python |

代码、真实资料、演示分别保存。关闭会话或归档一部小说不会删除共享人物/剧情库。文件由你掌握，复制到另一台电脑也可读取；异地备份需另行保存。

## 第一次蒸馏

把小说文件放入 `writing-vault/private-sources/incoming/`，或在对话中提供可读取的本地路径。然后可以说：

> 使用本项目的小说蒸馏工具，分析这本书。先索引章节，再分批蒸馏人物和剧情；把有价值的卡片存进 writing-vault，标明事实与推断，保留主线树和暗线关系图，每批保存进度。

模型负责阅读与判断，脚本负责提取文本、保存、版本、校验。大书按章节分批处理；报告会说明读到了哪里，未读部分不能算作完成。PDF 先通过宿主 PDF 工具提取；扫描件可能需要 OCR。

人物卡记录目标、需求、矛盾、关系、变化及依据。好片段记录事件如何起效：目标→障碍→选择→后果，以及适用条件和失效风险。默认保存概括与定位，不保存长篇原文摘录。

## 长期积累与跨作品使用

> 把这张人物卡标为收藏，加一条我的笔记：“适合关系缓慢建立的悬疑故事”。

> 从长期库找三个“隐瞒真相但仍推进信任”的场景机制，用于新小说《北岸》。先建立项目引用，再另建原创角色，不把参考人物直接当成我的人物。

> 记录这次改写：我把“守灯人的承诺”换成“医生的保密责任”。效果是人物动机更可信，但揭密需要提前安排病历线索。

共享库保存原始研究卡与抽象机制；每个创作项目引用明确版本并保存自己的原创实例。卡片升级不会悄悄改写旧项目。重新蒸馏会保留人工笔记、收藏与审阅状态。按人物名、机制关键词、标签、收藏、来源或项目检索都可。

## 读剧情图

主线树展示“作品→卷/篇章→场景”。关系网络展示跨节点联系；暗线可以横跨不同分段、连接多个节点，不必强行塞进一棵树。

点击节点看概述、依据、人物认知与读者认知；选择剧情线查看相关铺垫、误导和回收；用“分段”聚焦某卷/篇章。暗线状态包含未回收、部分回收、已回收、已放弃、未确认。演示来源是本项目自创短篇：`source-view` 保存有章节证据的分析，`views` 保存独立规划图；`inference` 表示解释性判断，`plan` 表示创作计划。

离线页面用于查看，编辑由对话或 CLI 保存后重新生成。它不是拖拽编辑器。目前已用小型完整示例验证交互，尚未用真实百万字小说验收分析质量或大图性能。

## 带到 ChatGPT，再带回来

1. 对 Codex 说：“为《北岸》导出这次写作需要的工作包。”或指定少数卡片。
2. 检查导出内容，把 `context.md`、`bundle.json`、`changes-template.json` 上传到需要的 ChatGPT 对话/项目。
3. 在 ChatGPT 中讨论和修改，要求按模板返回 `changes.json`。每个对象只使用模板中的一个可编辑版本，额外历史版本只供参考。
4. 将修改文件交回 Codex：“预检并回收这次修改；如有冲突，把本地和返回版本列给我。”

回收会比较共同基线、本地内容和返回内容。独立字段可合并，同字段冲突时整包不写入；重复回收同一个成功包不会重复创建卡片。操作细节见 [双端衔接](../references/chatgpt-handoff.md)。当前工作包是文件式衔接，并非自动同步 ChatGPT 记忆。

## 本机常用命令

在 `Novel` 目录打开 cmd，运行：

```bat
novel.cmd status
novel.cmd search --query 信任
novel.cmd search --favorite
novel.cmd projects
novel.cmd views
novel.cmd backup --output backups\my-library-001.zip
novel.cmd restore --file backups\my-library-001.zip --output restored-library-001
```

备份文件必须是新名字；恢复目录必须尚不存在。备份包含卡片、项目、来源索引、历史与工作包基线；原始小说不包含其中，需要自行保留。生成的 Markdown/HTML 可以重新生成。

通用环境从代码仓库运行 `python scripts/library.py --vault ../writing-vault <命令>`。所有子命令可用 `--help` 查看。成功输出 JSON；冲突返回码 3，输入或文件错误返回码 2。
